# 05. 출고 배치

마감 뒤 출고 지시를 만드는 배치의 흐름입니다. 대상 확정, 할당, 판정 발행, 센터별 출고 지시, 결과 검증 다섯 스텝으로 나눕니다. 설계 근거는 [05 풀필먼트와 배치](../design/05-풀필먼트-배치.md)에 있습니다.

| 흐름 | 언제 |
|---|---|
| [1. 출고 대상 등록](#1-출고-대상-등록) | 평소. PAID 이벤트가 올 때마다 |
| [2. 전체 흐름](#2-전체-흐름) | 매일 23:10 마감 회차 배치 |
| [3. 대상 확정](#3-대상-확정) | 배치 첫 스텝 |
| [4. 할당과 재시작](#4-할당과-재시작) | 배치 둘째 스텝, 저장 중에 죽었을 때 |
| [5. 센터별 출고 지시](#5-센터별-출고-지시) | 배치 넷째 스텝 |
| [6. 출고 예외와 검증 실패](#6-출고-예외와-검증-실패) | 사람이 처리해야 하는 경우 |

## 1. 출고 대상 등록

마감에 한꺼번에 읽지 않으려고 평소에 미리 쌓습니다.

```mermaid
sequenceDiagram
    autonumber
    participant 카프카 as order.events
    participant 풀필먼트
    participant DB as 풀필먼트 DB

    카프카->>풀필먼트: PAID (주문번호, 권역, 품목, paid_at)
    풀필먼트->>DB: 출고 대상이 없을 때만 삽입 (품목은 모두 대기 수량)
    opt 이미 있음 (중복 또는 취소 표시)
        Note right of DB: 아무 일도 하지 않음. 취소 표시를 되살리지 않음
    end
    카프카->>풀필먼트: CANCELLED (취소 품목과 수량, 사유)
    alt 고객 취소
        풀필먼트->>DB: 그 품목의 대기 수량을 취소 수량으로. 대상이 없으면 취소 표시 행만 삽입
    else 출고 불가, 관리자 취소
        Note right of 풀필먼트: 풀필먼트가 이미 수량을 옮김. 넘김
    end
```

## 2. 전체 흐름

```mermaid
sequenceDiagram
    autonumber
    participant 스케줄러
    participant 잡 as 출고 잡 (마감 시각 파라미터)
    participant 주문
    participant DB as 풀필먼트 DB

    스케줄러->>잡: 23:10 실행 (cutoff = 2026-10-28 23:00)
    Note over 잡: 같은 파라미터의 잡은 한 번만 실행됨
    잡->>주문: 1. 대상 확정 (회차 PAID 목록 대조)
    잡->>DB: TARGET_FIXED
    잡->>DB: 2. 할당 (스냅샷 고정, 메모리 계산, 1,000행씩 커밋)
    잡->>DB: ALLOCATED
    잡->>DB: 3. 판정 발행 (아웃박스 UNFILLABLE)
    잡->>DB: UNFILLABLE_PUBLISHED
    잡->>DB: 4. 센터별 출고 지시 (파티션 4개, 청크 500)
    잡->>DB: SHIPMENT_CREATED
    잡->>DB: 5. 결과 검증
    alt 예외 품목 0.1% 이하, 할당 입력 = 할당 결과 + 못 채운 판정, 할당 결과 = 출고 지시 품목 + 예외 품목
        잡->>DB: VERIFIED (배차 단계가 가져감)
    else 넘음
        잡->>DB: VERIFY_FAILED, 경보 (사람이 승인할 때까지 배차로 넘기지 않음)
    end
    Note over 스케줄러: 23:15 미시작, 00:30 ALLOCATED 아님, 00:50 SHIPMENT_CREATED 아님, 잡 실패면 경보
```

## 3. 대상 확정

이벤트가 밀리거나 처리 실패 토픽으로 빠진 주문도 원천과 대조해 채웁니다.

```mermaid
sequenceDiagram
    autonumber
    participant 스텝 as 대상 확정 스텝
    participant 주문
    participant DB as 풀필먼트 DB

    스텝->>주문: paid_at 이 (전 마감, 이번 마감] 인 PAID 주문번호 (페이지)
    주문-->>스텝: 주문번호 목록 (약 30만 건, 6MB)
    스텝->>DB: 출고 대상과 비교
    loop 대상에 없는 주문 (이벤트가 늦거나 DLT 로 빠진 주문)
        스텝->>주문: 주문 상세 (배송지, 권역, 품목, paid_at)
        스텝->>DB: 출고 대상 삽입
    end
    스텝->>DB: 배정 회차가 빈 대기 수량은 목록에 있는 주문만 이번 회차로
    스텝->>DB: 배정 회차가 이번 회차보다 이른 대기 수량(이월)도 이번 회차로
    스텝->>DB: 이번 범위의 paid_at 인데 목록에 없는 대상은 취소 표시, 대기 수량을 취소 수량으로
    alt 건수가 맞음
        스텝->>DB: 이번 회차의 대기 수량을 할당 입력 표에 복사 + TARGET_FIXED
    else 다름
        Note right of 스텝: 1분 뒤 다시. 세 번 다르면 차이 목록을 남기고 실패, 경보
    end
```

22:59:58 에 PAID 가 된 주문의 이벤트가 23:03 에 도착해도, 이 스텝이 주문 서비스 목록에서 찾아 넣습니다.
반대로 23:04 에 PAID 가 된 주문은 23:10 전에 이벤트로 등록돼도 목록에 없어 이번 회차에 오르지 않습니다.

## 4. 할당과 재시작

입력 품목과 재고를 모두 고정해, 저장 중간에 죽어 다시 계산해도 같은 결과가 나옵니다. 판정 이벤트는 할당이 끝난 뒤에 냅니다.

```mermaid
sequenceDiagram
    autonumber
    participant 스텝 as 할당 스텝
    participant DB as 풀필먼트 DB
    participant 입고 as 입고 처리

    스텝->>DB: 회차 상태 확인
    opt ALLOCATED 아님, 이전 결과가 일부 남음
        스텝->>DB: 이 회차의 할당 결과와 판정을 청크로 삭제
    end
    opt 이 회차의 스냅샷 없음
        스텝->>DB: 센터 실물 재고를 스냅샷으로 복사
    end
    입고->>DB: 배치 중 입고 (실물 재고만 바뀜, 스냅샷은 그대로)
    스텝->>DB: 할당 입력 표 90만 줄 + 스냅샷 읽기 (약 90MB). 품목 수량은 바꾸지 않음
    스텝->>스텝: paid_at, 주문번호 순으로 1차, 2차, 3차 배정과 판정
    loop 1,000행씩
        스텝->>DB: 할당 결과 + 못 채운 품목 판정 (한 트랜잭션)
    end
    스텝->>DB: ALLOCATED
```

배치 중 입고된 재고는 이번 할당에 쓰이지 않고 다음 회차에 쓰입니다. 결과가 바뀌지 않는 대가입니다.

## 5. 센터별 출고 지시

센터 4곳으로 나눠 병렬로 돌립니다. 각 파티션은 자기 센터의 실물 재고 행만 차감합니다.

```mermaid
sequenceDiagram
    autonumber
    participant 매니저 as 파티션 매니저
    participant 파티션 as 센터 파티션 (서울)
    participant DB as 풀필먼트 DB

    매니저->>파티션: 센터별 파티션 4개 실행
    loop 청크 500 (주문번호 순)
        파티션->>DB: 서울 센터의 할당 결과를 (센터, 주문) 단위로 묶어 읽기
        loop 청크 안의 출고 지시마다
            alt 출고 지시가 이미 있음 (재시작으로 다시 읽음)
                Note right of 파티션: 삽입도 차감도 하지 않음
            else 처음
                파티션->>DB: 품목 행과 서울 센터 재고 행을 상품번호 순으로 잠그고 확인
                alt 대기 수량과 재고가 충분하고 주소가 있음
                    파티션->>DB: 출고 지시 + 품목 삽입, 서울 센터 실물 재고 차감, 대기 수량을 출고 수량으로
                else 모자람 또는 주소 오류
                    파티션->>DB: 출고 예외 기록 + 대기 수량을 예외 수량으로 (같은 트랜잭션), 경보
                end
            end
        end
        파티션->>DB: 청크 커밋
    end
```

## 6. 출고 예외와 검증 실패

결제가 끝난 주문이라 자동으로 환불하지 않고 사람이 고릅니다.

```mermaid
sequenceDiagram
    autonumber
    actor 운영자
    participant 풀필먼트
    participant 주문

    풀필먼트-->>운영자: 출고 예외 경보 (예외 번호 17, 주문 E 의 부산 센터 품목, 주소 오류)
    alt 이월
        운영자->>풀필먼트: 출고 대상의 배송지 수정, 예외 OPEN 을 DEFERRED 로 + 예외 수량을 대기 수량으로, 배정 회차는 그대로
        Note right of 풀필먼트: 이미 출고된 수량은 그대로. 예외가 OPEN 이 아니면 0행이라 아무것도 하지 않음
    else 관리자 취소
        운영자->>풀필먼트: 관리자 취소 (예외 17)
        풀필먼트->>풀필먼트: 예외 OPEN 을 CANCELLED 로 + 예외 수량을 취소 수량으로 + 아웃박스 EXCEPTION_CANCELLED
        풀필먼트->>주문: fulfillment.events EXCEPTION_CANCELLED
        주문->>주문: 그 품목 수량 취소 + 환불 요청 refund-E-admin-17 + 아웃박스 CANCELLED (품목)
        Note right of 주문: 재고 서비스가 품목을 되돌리고 실사 부족분이 있으면 먼저 갚음
    end

    풀필먼트-->>운영자: 회차 VERIFY_FAILED 경보
    opt 잘못 만든 출고 지시가 있음 (배차 전)
        운영자->>풀필먼트: 출고 지시 취소. 실물 재고 되돌림, 출고 수량을 예외 수량으로, 출고 예외 OPEN
    end
    운영자->>풀필먼트: 원인을 고친 뒤 회차 승인
    풀필먼트->>풀필먼트: VERIFIED (배차 단계가 가져감)
```
