# 설계 문서

가상의 새벽배송 커머스에서 주문, 재고, 결제, 출고의 정합성을 어떻게 지키는지 정한 문서입니다.
각 문서는 문제를 숫자로 세우고, 선택지가 어디서 깨지는지 보고, 고른 것과 포기한 것을 함께 남깁니다.

## 설계 전체를 관통하는 원칙

- **외부 호출은 트랜잭션 밖에서 합니다.** 대행사가 느려져도 DB 커넥션이 묶이지 않습니다
- **결과는 성공, 실패, 모름 세 가지입니다.** 모름을 실패로 단정하지 않습니다
- **모든 상태 전이는 이전 상태를 조건으로 거는 갱신입니다.** 여러 경로가 같은 대상을 바꾸려 해도 하나만 이깁니다
- **결과가 늦게 확정되는 상태마다 주인 하나, 기한 하나, 경보 하나를 둡니다.** 01번 "수렴 책임" 표에 모았습니다
- **조용히 사라지는 경로를 두지 않습니다.** 버리는 상태 대신 재시도, 처리 실패 토픽, 사람이 처리할 표를 둡니다

## 범위

| 다루는 것 | 다루지 않는 것 |
|---|---|
| 주문, 재고, 결제, 출고 지시까지의 정합성 | 상품, 회원, 알림 서비스의 내부 |
| 장애와 재시작 뒤의 수렴 | 인증, 권한, 멀티 리전 |
| 처리량 가정과 거기서 나온 설계 값 | 피킹과 배차 |

## 고칠 때

구현이 설계와 달라지면 같은 커밋에서 설계 문서를 고칩니다.
결정을 바꿀 때는 그 문서의 "정리: 이 시스템의 선택" 표부터 고칩니다.
