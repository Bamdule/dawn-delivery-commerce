# API 문서

서비스마다 컨트롤러 테스트(Spring REST Docs)가 만든 요청과 응답 문서입니다.
문서에 없는 응답 필드가 생기거나 문서의 필드가 사라지면 그 테스트가 깨집니다. 그래서 문서가 코드와 어긋날 수 없습니다.

| 문서 | 담은 것 |
|---|---|
| [order-service](order-service.md) | 주문 생성, 다시 결제, 고객 취소, 주문 상세, 마감 회차의 결제 완료 목록, 환불 다시 요청, 아웃박스 관리, 처리 실패 토픽 관리 |
| [inventory-service](inventory-service.md) | 품절 목록, 예약, 결제 시작 표시, 거절 되돌림, 예약 상태, 판매 제한 권역, 슬롯 펴기, 재고 대사와 보정 |
| [payment-service](payment-service.md) | 승인, 회차 봉인, 회차 조회, 미결 회차 확정, 환불 접수와 조회와 확정 |
| [fulfillment-batch](fulfillment-batch.md) | 출고 예외 이월과 관리자 취소, 출고 지시 취소, 회차 시작과 승인, 대상 확정 차이와 보정, 입고와 실사, 실물 요약, 배차 인계 |

아웃박스 관리 API 는 이벤트를 내는 세 서비스(주문, 결제, 풀필먼트)에 같은 주소로 있어 주문 서비스 문서에만 적었습니다.
처리 실패 토픽 관리 API 도 이벤트를 받는 세 서비스(주문, 재고, 풀필먼트)에 같은 주소로 있어 주문 서비스 문서에만 적었습니다.

## 다시 만들기

```bash
./gradlew build apiDocs
```

예시의 주문 번호와 시각은 실행마다 달라집니다. 계약이 바뀐 것은 문서의 차이가 아니라 테스트의 실패로 압니다.
