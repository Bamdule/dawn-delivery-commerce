# 03. 이벤트 전달

아웃박스 릴레이가 이벤트를 보내는 흐름과, 받는 쪽이 처리하지 못한 메시지를 다루는 흐름입니다. 설계 근거는 [03 이벤트 전달 보장](../design/03-이벤트-전달-보장.md)에 있습니다.

| 흐름 | 언제 |
|---|---|
| [1. 아웃박스 릴레이](#1-아웃박스-릴레이) | 주문, 결제, 풀필먼트가 이벤트를 발행할 때 |
| [2. 릴레이가 중간에 죽을 때](#2-릴레이가-중간에-죽을-때) | 전송 뒤 기록 전에 릴레이가 죽을 때 |
| [3. 처리 실패 토픽](#3-처리-실패-토픽) | 받는 쪽이 재시도해도 처리하지 못할 때 |

## 1. 아웃박스 릴레이

락을 쥔 채 Kafka 를 기다리지 않도록 선점, 전송, 기록을 나눕니다.

```mermaid
sequenceDiagram
    autonumber
    participant 릴레이
    participant DB as 서비스 DB
    participant 카프카 as Kafka

    loop 200ms마다
        릴레이->>DB: PENDING 이고 시도 시각이 지났고 같은 키에 앞선 PENDING 이 없는 행 500건 (SKIP LOCKED)
        릴레이->>DB: 선점한 행의 다음 시도 시각을 30초 뒤로
        릴레이->>DB: 커밋 (락 해제)
        par 500건 비동기 전송
            릴레이->>카프카: send (키 = 주문번호, acks=all, 멱등 프로듀서, 전송 제한 20초)
        end
        카프카-->>릴레이: 전송 결과를 한꺼번에 받음
        릴레이->>DB: 성공은 SENT, 실패는 다음 시도 시각 (1초부터 두 배, 최대 60초, 지터)
    end
```

- **같은 키에 앞선 PENDING 이 있으면 뒤의 것을 집지 않습니다.** 앞선 것이 다시 시도를 기다리는 동안 뒤의 것이 앞질러 나가지 않습니다
- **릴레이가 여러 대여도 됩니다.** SKIP LOCKED 로 서로 다른 행을 집고, 선점 표시가 다음 주기의 중복 선택을 막습니다
- **10번 넘게 실패하면 경보를 내고 계속 시도합니다.** 버리는 상태는 없습니다
- **전송 제한 시간(20초)이 선점(30초)보다 짧습니다.** 늦게 끝난 전송이 다른 릴레이의 재전송과 겹치지 않습니다

## 2. 릴레이가 중간에 죽을 때

보낸 뒤 기록 전에 죽으면 같은 이벤트가 다시 나갑니다. 최소 한 번 전달의 성질이고 받는 쪽이 막습니다.

```mermaid
sequenceDiagram
    autonumber
    participant 릴레이A as 릴레이 1
    participant 릴레이B as 릴레이 2
    participant DB as 서비스 DB
    participant 카프카 as Kafka
    participant 소비자 as 받는 쪽

    릴레이A->>DB: 이벤트 E 선점 (다음 시도 23:00:30)
    릴레이A->>카프카: E 전송 성공
    Note over 릴레이A: SENT 기록 전에 죽음
    카프카->>소비자: E 처리 (예약 확정 1행)
    Note over DB: 23:00:30 선점 만료. E 는 아직 PENDING
    릴레이B->>DB: E 다시 선점
    릴레이B->>카프카: E 다시 전송
    릴레이B->>DB: E SENT
    카프카->>소비자: E 다시 처리
    소비자->>소비자: 조건부 갱신 0행 또는 인박스에 있음. 넘김
```

이벤트 아이디는 사실(주문번호와 사건)에서 만들어서, 다시 나간 E 도 같은 아이디입니다. 인박스가 중복을 거를 수 있습니다.

## 3. 처리 실패 토픽

재시도해도 실패하는 메시지를 로그만 남기고 넘기면 그 주문은 조용히 사라집니다. 처리 실패 토픽에 남기고 사람이 다시 넣습니다.

```mermaid
sequenceDiagram
    autonumber
    participant 카프카 as order.events
    participant 소비자 as 풀필먼트 소비자
    participant DLT as order.events-dlt
    actor 운영자

    카프카->>소비자: PAID (주문 A, 배송지 권역 누락)
    소비자->>소비자: 실패. 1초, 2초, 4초 뒤 재시도
    소비자->>DLT: 같은 키로 보냄
    소비자-->>카프카: 오프셋 커밋 (다음 메시지 진행)
    DLT-->>운영자: 적재 1건 경보
    카프카->>소비자: CANCELLED (주문 A) 가 먼저 도착하는 경우
    소비자->>소비자: 출고 대상에 없는 주문이라 취소 표시 행만 남김
    운영자->>운영자: 원인 수정 (주문 A 권역 보정)
    운영자->>카프카: 관리 명령으로 DLT 의 메시지를 원래 토픽에 다시 넣음
    카프카->>소비자: PAID (주문 A) 다시 처리
    alt 취소 표시 행이 있음
        Note right of 소비자: 되살리지 않음
    else 없음
        소비자->>소비자: 출고 대상 등록
    end
```

운영자가 다시 넣지 못한 채 마감이 오더라도, 출고 배치의 대상 확정 스텝이 주문 서비스 목록과 대조해 주문 A 를 채웁니다.
